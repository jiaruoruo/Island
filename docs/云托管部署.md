# 微信云托管（CloudBase Run）部署步骤

基于本项目已完成的改造，按下面顺序执行即可。云托管用 `callContainer` 调用，**无需域名、无需 ICP 备案**。

---

## 1）开通云托管环境

1. 打开 [cloud.weixin.qq.com](https://cloud.weixin.qq.com)（或 mp 后台 → 云开发）→ 开通。
2. 创建环境，记下**环境 ID**（形如 `island-1a2b3c`）。
3. 小程序基础库 ≥ **2.21.1**（本项目 3.5.0 ✅）。

## 2）创建云数据库（PostgreSQL）

1. 云开发控制台 → 数据库 → 新建 PostgreSQL 实例（或云托管 → 云数据库）。
2. 拿到连接串，例如：
   ```
   postgresql://user:pass@host:5432/island?schema=public
   ```
3. 记下来，第 4 步填到环境变量 `DATABASE_URL`。

## 3）前端填云托管配置（`miniprogram/app.js`）

```js
cloudEnv: 'island-1a2b3c',        // ← 第 1 步的环境 ID
serviceName: 'island-server',     // ← 第 4 步创建的服务名，保持一致
forceCloud: false,                // 想让「真机调试」也走云托管就设 true
```

代码已按环境自动判定：`trial`/`release` 自动走云托管；`develop` 仍走局域网（`LAN_BASE`），互不影响。

## 4）部署后端服务

**方式 A：云开发 CLI**
```bash
npm i -g @cloudbase/cli
tcb login
cd server
tcb cloudrun deploy
```

**方式 B：控制台**
云托管 → 服务 → 新建服务 → 选择「本地代码 / Dockerfile」→ 上传 `server/` 目录 → 构建部署。

**服务环境变量（必填）**

| 变量 | 值 |
|---|---|
| `STORE` | `prisma` |
| `DATABASE_URL` | 第 2 步的连接串 |
| `MOCK_AUTH` | `true`（先用 mock 登录）；要真实登录设 `false` 并填 `WX_SECRET` |
| `MOCK_AI` | `true`（先用 mock AI）；接真实大模型设 `false` |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | `MOCK_AI=false` 时填 |

健康检查路径填 `/api/health`（项目已自带）。

> 容器启动时会检测 `STORE=prisma` 并自动执行 `prisma migrate deploy`（迁移 SQL 已在 `server/prisma/migrations/`）。

## 5）上传小程序 → 体验版验证

1. 开发者工具 **上传**。
2. mp 后台 → 管理 → 版本管理 → 设为**体验版** → 添加体验成员 → 扫码测试。
3. **无需**在 mp 后台配置 `request 合法域名` / `socket 合法域名`（云托管免域名）。

## 6）发布上线

- 云托管免域名备案，但**小程序备案仍需做**：mp 后台 → 设置 → 小程序备案。
- 备案通过 → 提交审核 → 发布。

## 已完成的改造（代码侧）

| 文件 | 改动 |
|---|---|
| `miniprogram/app.js` | `wx.cloud.init` + `cloudEnv`/`serviceName`/`forceCloud`，按环境自动切换 |
| `miniprogram/utils/request.js` | 云托管走 `wx.cloud.callContainer`，否则仍走 `wx.request` |
| `miniprogram/utils/ws.js` | 云托管走 `wx.cloud.connectContainer`；统一返回 `send/close` 句柄，并修复「主动关闭后仍重连」的泄漏 |
| `server/Dockerfile` | 构建 `prisma generate` + `npm run build`；`STORE=prisma` 时启动前自动迁移 |
| `server/prisma/migrations/` | 已生成初始迁移 SQL（`prisma migrate deploy` 可直接用） |

---

## 必须注意的限制

| 限制 | 说明 |
|---|---|
| **必须用 `callContainer`** | 若用 `wx.request` 打云托管公网域名，仍受 `request 合法域名` 限制，仍需备案 |
| 超时 ≤ 15s | `callContainer` 上限，AI 慢回复需优化 |
| 请求体 ≤ 100K | 图片用云存储，别走请求体 |
| iOS 高性能+ 模式 | `connectContainer` 读不到 `x-wx-openid` |
| 冷启动 | 可在控制台设置实例常驻 |

## 7）`server/` 部署命令清单（照抄执行）

### 第 0 步：本地准备

```bash
# 1. 安装云开发 CLI
npm i -g @cloudbase/cli

# 2. 登录（浏览器扫码）
tcb login

# 3. 确认环境 ID（应能看到 prod-d6g2qc4i821472162）
tcb env list
```

### 第 1 步：（可选）本地先验证镜像能跑

需要 Docker Desktop。

```bash
cd server
docker build -t island-server .
docker run --rm -p 8080:8080 island-server
# 另开一个终端验证健康检查
curl http://localhost:8080/api/health
```

期望返回：
```json
{"ok":true,"store":"memory","aiMode":"mock","authMode":"mock"}
```
`Ctrl+C` 停掉容器。

### 第 2 步：创建云数据库（PostgreSQL）

控制台 → 云开发 → 数据库 → 新建 PostgreSQL 实例 → 得到连接串：

```
postgresql://user:pass@host:5432/island?schema=public
```

> 数据库与云托管选**同一地域/环境**，走内网更快更稳。

### 第 3 步：部署服务（三选一）

**方式 A：代码库 + Dockerfile（推荐）**

云托管 → 服务列表 → 新建服务 → 部署方式选「**代码库**」→ 授权并关联 `github.com/jiaruoruo/Island` → 代码目录填 `server` → 选 Dockerfile 构建。

优点：云上构建，`.dockerignore` 生效（不含 `node_modules`），**以后 git push 即自动重新部署**。

**方式 B：本地代码上传**

```powershell
# 务必先删掉这两个目录再打包，否则包体积过大
cd server
Remove-Item -Recurse -Force node_modules, dist -ErrorAction SilentlyContinue
# 然后打包 server 目录为 zip，在控制台「本地代码」上传
```

**方式 C：CLI 部署**

```bash
cd server
tcb cloudrun deploy
# 按交互提示选择：环境 prod-d6g2qc4i821472162 → 服务名 island-server → 本地代码
```

### 第 4 步：服务配置（关键）

| 配置项 | 值 |
|---|---|
| 服务名 | `island-server`（**必须与 `app.js` 的 `serviceName` 一致**） |
| 监听端口 | `8080`（云托管探针默认探测 8080，必须一致） |
| 环境变量 `PORT` | `8080`（容器监听端口，与上面一致） |
| 健康检查路径 | `/api/health` |

**环境变量完整清单**

| 变量 | 值 | 说明 |
|---|---|---|
| `PORT` | `8080` | 与监听端口一致 |
| `STORE` | `prisma` | 持久化；改 `memory` 则重启丢数据 |
| `DATABASE_URL` | `postgresql://user:pass@host:5432/island?schema=public` | 第 2 步的连接串 |
| `MOCK_AUTH` | `true` | 先用 mock 登录；真实登录改 `false` + 填 `WX_SECRET` |
| `MOCK_AI` | `true` | 先用 mock AI；接大模型改 `false` |
| `LLM_BASE_URL` | （可选） | `MOCK_AI=false` 时填 |
| `LLM_API_KEY` | （可选） | 同上 |
| `LLM_MODEL` | （可选） | 同上 |

### 第 5 步：验证部署

1. 服务详情 → **日志**，看到 `[twoo-server] ready` 即启动成功。
2. 临时开启「公网访问」，用公网域名验证：
   ```bash
   curl https://<你的公网域名>/api/health
   ```
3. 验证通过后**建议关闭公网访问**（只走 `callContainer`，更安全、防 DDoS）。
4. 确认建表成功：日志里应有 `prisma migrate deploy` 执行记录（无报错）。

### 第 6 步：小程序联调

```bash
# 开发者工具：上传 → mp 后台设为体验版 → 手机扫码
```

此时 `app.js` 已配好：
- `cloudEnv: 'prod-d6g2qc4i821472162'`
- `serviceName: 'island-server'`
- `forceCloud: true`（真机调试也走云端）
- 模拟器仍走本地 `localhost:3000`

## 9）部署排错表

| 现象 | 原因 / 解决 |
|---|---|
| 服务起不来 / 探针报 `dial tcp ...:8080: connect: connection refused` | 端口不一致：容器实际监听端口 ≠ 8080。确认「监听端口」+ `PORT` 环境变量都是 `8080` |
| 日志报 Prisma 连接失败 | `DATABASE_URL` 填错，或数据库与云托管不同地域/未放行 |
| 日志报 `PrismaClient` 未生成 | Dockerfile 已含 `prisma generate`；改了 `schema.prisma` 需重新部署 |
| 表不存在 | 容器启动时自动 `prisma migrate deploy`；看日志是否执行/报错 |
| 小程序报 `request:fail url not in domain list` | **用了 `wx.request` 打公网域名**；必须走 `wx.cloud.callContainer` |
| 调用超时 | `callContainer` 上限 15s，AI 慢需优化 |
| 首次访问很慢 | 冷启动；控制台设置最小实例数 1 / 常驻 |
| 不支持 Docker Compose | 数据库要用独立云数据库 |
